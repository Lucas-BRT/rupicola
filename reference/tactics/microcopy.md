# Microcopy tactics

Shared rules: [common](../common.md), [index](index.md). Thresholds: [content module](../ux/content.md).

### Verb-first buttons
Use when: any action. Do: a specific verb plus object ("Save changes", "Add member"). Avoid: OK, Submit, Yes and No.

### Labels in the user's words
Use when: fields and menu items. Do: use the user's term, one term per concept across the app. Avoid: internal names and alternating synonyms.

### Error message anatomy
Use when: any error. Do: what happened, why, how to fix, with the exact value or file when known. Avoid: error codes, blame, "Invalid input".

### Confirmation text
Use when: destructive prompts. Do: title states the decision, body the consequence, buttons the action ("Delete 3 files"), Cancel as the safe default. Avoid: "Are you sure?" and OK.

### Empty-state text
Use when: nothing to show. Do: say why, what it will contain, and the next action in one line. Avoid: only an illustration.

### Helper text and hints
Use when: a field has a rule or example. Do: put the rule before the user fails, short, below the field and tied to it. Avoid: hiding rules in placeholders.

### Tooltips
Use when: a control needs a name or a shortcut. Do: a short name, the shortcut, shown on hover and focus, dismissible. Avoid: essential information that exists only in a tooltip.

### Progress and status text
Use when: long operations. Do: name the step and amount ("Importing 12 of 40 files"). Avoid: "Please wait".

### Notification text
Use when: toasts and system notifications. Do: lead with the object and outcome, add the action, keep it short. Avoid: marketing, repeated app names.

### Permission and consent text
Use when: asking for access. Do: say what, why and what happens if declined, in plain terms. Avoid: dark patterns and pre-checked consent.

### Tone and voice
Use when: setting the writing style. Do: be clear first, friendly second, calm in errors, consistent person and tense across the app. Avoid: humor in failures and exclamation marks.

### Casing and punctuation
Use when: UI text. Do: choose sentence case or title case once, no trailing periods on labels, ellipsis only for actions that need more input ("Save as..."). Avoid: mixed styles.

### Numbers, dates and units
Use when: values in text. Do: formatted for the locale, units spelled or standard, relative time with the absolute available. Avoid: concatenated number strings.

### Truncation and long text
Use when: limited space. Do: truncate in the middle for paths and IDs, at the end for prose, always make the full text available, never truncate errors. Avoid: cutting meaning.

### Instructional text
Use when: onboarding and help. Do: short steps in task order, one action per sentence, pair with the control. Avoid: manuals inside the interface.

### Whole messages
Use when: dynamic text. Do: write full sentences with named placeholders and plural forms, so translation works. Avoid: assembled fragments.
